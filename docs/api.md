# Trade for All — API

Базовый URL (локально): `http://localhost:8080`

Формат данных — JSON. Все ручки `/v1/*` вызываются **сервером игры**, а не клиентом игрока.

## Авторизация

Каждый запрос к `/v1/*` должен содержать заголовок с API-ключом игры:

```
X-API-Key: demo-survival-key
```

По ключу определяется игра. Все данные (лоты) изолированы по играм: запрос с ключом одной игры никогда не видит лоты другой.

Тестовые ключи из сидов:

| Игра          | X-API-Key           |
|---------------|---------------------|
| Demo Survival | `demo-survival-key` |
| Demo RPG      | `demo-rpg-key`      |

## Формат ошибок

Все ошибки возвращаются в одном формате:

```json
{
  "error": {
    "code": "validation_error",
    "message": "limit: must be between 1 and 100"
  }
}
```

| HTTP | code               | Когда                                     |
|------|--------------------|-------------------------------------------|
| 400  | `validation_error` | Некорректные параметры запроса            |
| 401  | `unauthorized`     | Нет заголовка `X-API-Key` или ключ неверен |
| 403  | `not_owner`        | Операция доступна только продавцу лота     |
| 404  | `not_found`        | Ресурс не найден                          |
| 409  | `listing_not_active` | Лот уже продан или снят                 |
| 409  | `own_listing`      | Продавец пытается купить свой лот          |
| 409  | `price_mismatch`   | Цена лота изменилась                       |
| 422  | `idempotency_key_reused` | `Idempotency-Key` уже использован для другого запроса |
| 500  | `internal_error`   | Внутренняя ошибка сервиса                 |

## Идемпотентность

Все `POST` и `PATCH` требуют заголовок:

```
Idempotency-Key: 3f1c9a7e-5b2d-4c8e-9f10-2a6b7c8d9e0f
```

Ключ генерирует сервер игры (рекомендуется UUID v4), максимум 255 символов.
Ключи изолированы по играм: одинаковый ключ у двух игр — это два разных ключа.

Правила:

- Повтор запроса с **тем же ключом и тем же телом** не выполняет операцию заново, а возвращает сохранённый результат первого успешного выполнения с тем же HTTP-статусом.
- Тот же ключ с **другим телом** или для другой операции — ошибка `422 idempotency_key_reused`.
- Сохраняются только успешные результаты. Если запрос завершился ошибкой (`400`, `409`, `500`), в базе ничего не изменилось, и повтор с тем же ключом выполнится заново.
- Если два запроса с одним ключом пришли одновременно, операция выполнится один раз, оба получат один и тот же результат.

Что делать серверу игры:

1. Сгенерировать ключ **до** первой попытки и сохранить его вместе с намерением.
2. При таймауте, обрыве соединения или `5xx` — повторить запрос **с тем же ключом**.
3. Новый ключ — только для новой операции.

Таймаут не означает, что операция не выполнилась: возможно, сервис всё сделал, а ответ потерялся. Повтор с тем же ключом безопасно это выяснит.

## Модель лота

| Поле         | Тип     | Описание                                      |
|--------------|---------|-----------------------------------------------|
| `id`         | integer | Идентификатор лота                            |
| `seller_id`  | string  | Id игрока-продавца в игре                     |
| `item_code`  | string  | Тип предмета в игре, например `iron_sword`    |
| `quantity`   | integer | Количество предметов в лоте (> 0)             |
| `price`      | integer | Цена всего лота во внутриигровой валюте (> 0) |
| `status`     | string  | `active`, `sold`, `cancelled`                 |
| `created_at` | string  | Время создания, RFC 3339                      |

## GET /v1/listings — витрина

Возвращает **активные** лоты игры, от новых к старым. Проданные и отменённые лоты не возвращаются.

### Query-параметры

| Параметр    | Обязательный | Описание                                                                 |
|-------------|--------------|--------------------------------------------------------------------------|
| `item_code` | нет          | Только лоты с этим типом предмета                                        |
| `seller_id` | нет          | Только лоты этого продавца («мои лоты»)                                  |
| `limit`     | нет          | Размер страницы, целое от 1 до 100. По умолчанию 20                      |
| `cursor`    | нет          | Значение `next_cursor` из предыдущего ответа. Без него — первая страница |

Фильтры можно комбинировать.

### Пагинация

Курсорная. Курсор — непрозрачная строка, клиент не должен её разбирать или собирать сам.
Чтобы получить следующую страницу, передайте `next_cursor` из ответа в параметр `cursor`, сохранив те же фильтры.
`next_cursor: null` означает, что страниц больше нет.

В отличие от `offset`, курсор не пропускает и не дублирует лоты, если между запросами появились новые.

### Ответ 200

```json
{
  "items": [
    {
      "id": 5,
      "seller_id": "masha",
      "item_code": "iron_sword",
      "quantity": 1,
      "price": 90,
      "status": "active",
      "created_at": "2026-10-02T12:50:00Z"
    },
    {
      "id": 1,
      "seller_id": "vasya",
      "item_code": "iron_sword",
      "quantity": 1,
      "price": 100,
      "status": "active",
      "created_at": "2026-10-02T11:00:00Z"
    }
  ],
  "next_cursor": null
}
```

Если лотов нет, возвращается `"items": []`.

### Ошибки

| HTTP | code               | Когда                                     |
|------|--------------------|-------------------------------------------|
| 400  | `validation_error` | `limit` не число или вне диапазона 1–100  |
| 400  | `validation_error` | `cursor` повреждён                        |
| 401  | `unauthorized`     | Нет `X-API-Key` или ключ неверен          |

### Примеры

```bash
# первая страница витрины
curl -H "X-API-Key: demo-survival-key" "http://localhost:8080/v1/listings"

# все железные мечи, по 2 на страницу
curl -H "X-API-Key: demo-survival-key" "http://localhost:8080/v1/listings?item_code=iron_sword&limit=2"

# следующая страница
curl -H "X-API-Key: demo-survival-key" "http://localhost:8080/v1/listings?item_code=iron_sword&limit=2&cursor=<next_cursor>"

# лоты продавца vasya
curl -H "X-API-Key: demo-survival-key" "http://localhost:8080/v1/listings?seller_id=vasya"
```

## POST /v1/listings — выставить лот

Создаёт активный лот. К моменту вызова сервер игры **уже изъял** предмет из инвентаря игрока: с этого момента предмет существует только в лоте.

Если запрос завершился ошибкой, лот не создан, и предмет нужно вернуть игроку. При таймауте предмет не возвращать, а повторить запрос с тем же `Idempotency-Key`.

### Заголовки

| Заголовок         | Обязательный |
|-------------------|--------------|
| `X-API-Key`       | да           |
| `Idempotency-Key` | да           |
| `Content-Type: application/json` | да |

### Тело запроса

| Поле        | Тип     | Ограничения             | Описание                       |
|-------------|---------|-------------------------|--------------------------------|
| `seller_id` | string  | 1–64 символа            | Id игрока-продавца в игре      |
| `item_code` | string  | 1–64 символа            | Тип предмета в игре            |
| `quantity`  | integer | 1–2147483647            | Количество предметов в лоте    |
| `price`     | integer | > 0                     | Цена всего лота                |

Все поля обязательны. Неизвестные поля — ошибка. Максимальный размер тела — 64 КБ.

```json
{
  "seller_id": "vasya",
  "item_code": "wolf_pelt",
  "quantity": 50,
  "price": 200
}
```

### Ответ 201

Созданный лот (см. [модель лота](#модель-лота)):

```json
{
  "id": 14,
  "seller_id": "vasya",
  "item_code": "wolf_pelt",
  "quantity": 50,
  "price": 200,
  "status": "active",
  "created_at": "2026-10-02T14:05:31.218Z"
}
```

Повтор с тем же `Idempotency-Key` и тем же телом вернёт `201` с **тем же** лотом (тот же `id`), новый лот не создаётся.

### Ошибки

| HTTP | code                     | Когда                                                     |
|------|--------------------------|-----------------------------------------------------------|
| 400  | `validation_error`       | Нет `Idempotency-Key` или он длиннее 255 символов         |
| 400  | `validation_error`       | Тело не JSON, лишние поля, неверные типы или ограничения  |
| 401  | `unauthorized`           | Нет `X-API-Key` или ключ неверен                          |
| 422  | `idempotency_key_reused` | Этот `Idempotency-Key` уже использован с другим телом     |

### Пример

```bash
curl -X POST "http://localhost:8080/v1/listings" \
  -H "X-API-Key: demo-survival-key" \
  -H "Idempotency-Key: 3f1c9a7e-5b2d-4c8e-9f10-2a6b7c8d9e0f" \
  -H "Content-Type: application/json" \
  -d '{"seller_id":"vasya","item_code":"wolf_pelt","quantity":50,"price":200}'
```

## POST /v1/listings/{id}/buy — купить лот

Продаёт лот покупателю. Лот переходит в статус `sold` и больше не появляется на витрине.

Сервис **не хранит балансы**: валюту списывает и начисляет сервер игры.

Порядок действий сервера игры:

1. Проверить, что у покупателя есть `price` валюты, и **списать** её.
2. Вызвать `buy` с новым `Idempotency-Key`.
3. По ответу `200` — выдать покупателю `item`, начислить продавцу `amount` (даже если продавец офлайн).
4. По ответу `4xx` — вернуть покупателю списанную валюту. Покупка не состоялась.
5. По таймауту или `5xx` — **не возвращать** валюту, а повторить запрос с тем же ключом, пока не придёт `200` или `4xx`.

### Почему в запросе цена

Продавец может изменить цену лота (`PATCH`) между тем, как покупатель увидел лот, и нажатием «Купить».
Сервер игры списывает ту цену, которую видел покупатель, и передаёт её в `price`.
Если цена лота другая, покупка не проходит (`409 price_mismatch`), и сумма списания всегда совпадает с суммой, которую получит продавец.

### Заголовки

| Заголовок         | Обязательный |
|-------------------|--------------|
| `X-API-Key`       | да           |
| `Idempotency-Key` | да           |
| `Content-Type: application/json` | да |

### Параметры пути

| Параметр | Описание   |
|----------|------------|
| `id`     | Id лота    |

### Тело запроса

| Поле       | Тип     | Ограничения  | Описание                                         |
|------------|---------|--------------|--------------------------------------------------|
| `buyer_id` | string  | 1–64 символа | Id игрока-покупателя в игре                      |
| `price`    | integer | > 0          | Цена, которую видел покупатель и списала игра    |

```json
{
  "buyer_id": "petya",
  "price": 100
}
```

### Ответ 200

Что сервер игры должен выдать по итогам сделки:

| Поле            | Описание                                  |
|-----------------|-------------------------------------------|
| `listing_id`    | Id проданного лота                        |
| `buyer_id`      | Кому выдать предмет                       |
| `item.code`     | Какой предмет выдать                      |
| `item.quantity` | Сколько штук                              |
| `seller_id`     | Кому начислить выручку                    |
| `amount`        | Сколько валюты начислить продавцу         |

```json
{
  "listing_id": 1,
  "buyer_id": "petya",
  "item": { "code": "iron_sword", "quantity": 1 },
  "seller_id": "vasya",
  "amount": 100
}
```

Повтор с тем же `Idempotency-Key` и тем же телом вернёт `200` с тем же ответом, даже если лот уже продан этим запросом. Выдавать предмет повторно не нужно: это тот же результат.

### Ошибки

Все ошибки ниже означают, что покупка **не состоялась**: лот не изменился.

| HTTP | code                     | Когда                                                       |
|------|--------------------------|-------------------------------------------------------------|
| 400  | `validation_error`       | `id` не число, нет `Idempotency-Key`, неверное тело запроса |
| 401  | `unauthorized`           | Нет `X-API-Key` или ключ неверен                            |
| 404  | `not_found`              | Лота нет или он принадлежит другой игре                     |
| 409  | `listing_not_active`     | Лот уже продан или снят с продажи                           |
| 409  | `own_listing`            | `buyer_id` совпадает с продавцом                            |
| 409  | `price_mismatch`         | Цена лота не равна `price` из запроса                       |
| 422  | `idempotency_key_reused` | Этот `Idempotency-Key` уже использован с другим запросом    |

### Гарантии

- Лот продаётся ровно один раз. Если два покупателя нажали «Купить» одновременно, один получит `200`, второй — `409 listing_not_active`.
- Повтор с тем же ключом никогда не продаёт лот второй раз и всегда получает исходный результат.

### Пример

```bash
curl -X POST "http://localhost:8080/v1/listings/1/buy" \
  -H "X-API-Key: demo-survival-key" \
  -H "Idempotency-Key: 9b2e4f6a-1c3d-4e5f-8a7b-6c5d4e3f2a1b" \
  -H "Content-Type: application/json" \
  -d '{"buyer_id":"petya","price":100}'
```

## POST /v1/listings/{id}/cancel — снять лот с продажи

Снимает активный лот. Лот переходит в статус `cancelled` и больше не появляется на витрине.
Снять лот может только его продавец.

Порядок действий сервера игры:

1. Вызвать `cancel` с новым `Idempotency-Key`.
2. По ответу `200` — вернуть продавцу `item`.
3. По ответу `4xx` — ничего не делать: лот не снят (например, его уже купили).
4. По таймауту или `5xx` — повторить запрос с тем же ключом.

### Заголовки

| Заголовок         | Обязательный |
|-------------------|--------------|
| `X-API-Key`       | да           |
| `Idempotency-Key` | да           |
| `Content-Type: application/json` | да |

### Параметры пути

| Параметр | Описание |
|----------|----------|
| `id`     | Id лота  |

### Тело запроса

| Поле        | Тип    | Ограничения  | Описание                                   |
|-------------|--------|--------------|--------------------------------------------|
| `seller_id` | string | 1–64 символа | Id игрока, который снимает лот. Должен совпадать с продавцом |

```json
{
  "seller_id": "vasya"
}
```

### Ответ 200

Какой предмет сервер игры должен вернуть продавцу:

```json
{
  "listing_id": 2,
  "seller_id": "vasya",
  "item": { "code": "wolf_pelt", "quantity": 50 }
}
```

Повтор с тем же `Idempotency-Key` и тем же телом вернёт `200` с тем же ответом. Возвращать предмет повторно не нужно.

### Ошибки

Все ошибки ниже означают, что лот **не снят**.

| HTTP | code                     | Когда                                                       |
|------|--------------------------|-------------------------------------------------------------|
| 400  | `validation_error`       | `id` не число, нет `Idempotency-Key`, неверное тело запроса |
| 401  | `unauthorized`           | Нет `X-API-Key` или ключ неверен                            |
| 403  | `not_owner`              | `seller_id` не совпадает с продавцом лота                   |
| 404  | `not_found`              | Лота нет или он принадлежит другой игре                     |
| 409  | `listing_not_active`     | Лот уже продан или снят                                     |
| 422  | `idempotency_key_reused` | Этот `Idempotency-Key` уже использован с другим запросом    |

Если продавец снимает лот, а покупатель в тот же момент его покупает, выполнится ровно одна операция. Вторая получит `409 listing_not_active`.

### Пример

```bash
curl -X POST "http://localhost:8080/v1/listings/2/cancel" \
  -H "X-API-Key: demo-survival-key" \
  -H "Idempotency-Key: 5d4c3b2a-1f0e-4d9c-8b7a-6f5e4d3c2b1a" \
  -H "Content-Type: application/json" \
  -d '{"seller_id":"vasya"}'
```

## PATCH /v1/listings/{id} — изменить цену лота

Меняет цену активного лота. Менять цену может только продавец. Другие поля лота не меняются.

Если покупатель в этот момент покупает лот по старой цене, покупка не пройдёт (`409 price_mismatch`): покупатель должен увидеть новую цену.

### Заголовки

| Заголовок         | Обязательный |
|-------------------|--------------|
| `X-API-Key`       | да           |
| `Idempotency-Key` | да           |
| `Content-Type: application/json` | да |

### Параметры пути

| Параметр | Описание |
|----------|----------|
| `id`     | Id лота  |

### Тело запроса

| Поле        | Тип     | Ограничения  | Описание                                                    |
|-------------|---------|--------------|-------------------------------------------------------------|
| `seller_id` | string  | 1–64 символа | Id игрока, который меняет цену. Должен совпадать с продавцом |
| `price`     | integer | > 0          | Новая цена всего лота                                        |

```json
{
  "seller_id": "vasya",
  "price": 150
}
```

### Ответ 200

Лот с новой ценой (см. [модель лота](#модель-лота)):

```json
{
  "id": 1,
  "seller_id": "vasya",
  "item_code": "iron_sword",
  "quantity": 1,
  "price": 150,
  "status": "active",
  "created_at": "2026-10-02T11:00:00Z"
}
```

### Ошибки

Все ошибки ниже означают, что цена **не изменилась**.

| HTTP | code                     | Когда                                                       |
|------|--------------------------|-------------------------------------------------------------|
| 400  | `validation_error`       | `id` не число, нет `Idempotency-Key`, неверное тело запроса |
| 401  | `unauthorized`           | Нет `X-API-Key` или ключ неверен                            |
| 403  | `not_owner`              | `seller_id` не совпадает с продавцом лота                   |
| 404  | `not_found`              | Лота нет или он принадлежит другой игре                     |
| 409  | `listing_not_active`     | Лот уже продан или снят                                     |
| 422  | `idempotency_key_reused` | Этот `Idempotency-Key` уже использован с другим запросом    |

### Пример

```bash
curl -X PATCH "http://localhost:8080/v1/listings/1" \
  -H "X-API-Key: demo-survival-key" \
  -H "Idempotency-Key: 7e6d5c4b-3a2f-4e1d-9c8b-7a6f5e4d3c2b" \
  -H "Content-Type: application/json" \
  -d '{"seller_id":"vasya","price":150}'
```

## Служебные ручки

Не требуют `X-API-Key`.

| Ручка          | Ответ                                                      |
|----------------|------------------------------------------------------------|
| `GET /healthz` | `200` — процесс жив                                        |
| `GET /readyz`  | `200` — сервис готов принимать трафик, `503` — БД недоступна |
