# Отчёт по заданию 2

Запустил свой проект Trade for All из первого задания в minikube. В compose было три сервиса: `postgres`, `migrate` и `app`, их и перенёс в Kubernetes. Код приложения менять не пришлось.

## Сборка образов

Образов два:
- `trade-app:0.1.0` - приложение, `Dockerfile` в корне (с первого задания);
- `trade-migrate:0.1.0` - миграции, `hw2/migrate.Dockerfile`. В compose миграции подключались как папка с диска, в Kubernetes так не сделать, поэтому положил их в образ на основе `migrate/migrate`.

Сборка в docker-демоне minikube (у меня Windows, поэтому PowerShell):

```powershell
& minikube -p minikube docker-env --shell powershell | Invoke-Expression
docker build -t trade-app:0.1.0 .
docker build -f hw2/migrate.Dockerfile -t trade-migrate:0.1.0 .
```

Или собрать обычным Docker и загрузить:

```powershell
minikube image load trade-app:0.1.0
minikube image load trade-migrate:0.1.0
```

В манифестах `imagePullPolicy: IfNotPresent`, чтобы Kubernetes не пытался скачать образы из Docker Hub.

## Какие абстракции Kubernetes использованы

Манифесты лежат в `hw2/k8s/`, номер в имени файла задаёт порядок применения.

| compose | Kubernetes |
|---|---|
| `.env` | Secret + ConfigMap |
| `postgres` + volume | StatefulSet + PVC + Service |
| `migrate` | Job |
| `app` | Deployment + Service NodePort |
| `depends_on` | initContainers |
| `healthcheck` | readinessProbe / livenessProbe |

- **Namespace `trade`** - всё приложение в отдельном пространстве имён, удобно смотреть и удалять.
- **Secret `postgres-credentials`** - логин, пароль, имя базы и `DATABASE_URL`. Подключается через `secretKeyRef`.
- **ConfigMap `trade-app`** - `HTTP_ADDR` и `SHUTDOWN_TIMEOUT`, подключается через `envFrom`.
- **StatefulSet `postgres`** - одна реплика, постоянное имя пода `postgres-0` и свой диск, который остаётся при пересоздании пода.
- **PVC / PV / StorageClass** - диск 1Gi для базы, в minikube его создаёт StorageClass `standard`.
- **Service `postgres`** (ClusterIP) - по имени `postgres` в базу ходят приложение и миграции.
- **Job `trade-migrate`** - миграции запускаются один раз и завершаются (`Completed`).
- **Deployment `trade-app`** - 2 реплики приложения, пробы `/readyz` (есть ли связь с базой) и `/healthz`, лимиты ресурсов, `RollingUpdate` с `maxUnavailable: 0`.
- **Service `trade-app`** (NodePort 30080) - вход в приложение снаружи кластера.
- **initContainers** - в Job ждёт, пока поднимется база (`pg_isready`), в Deployment ждёт, пока применятся миграции. Благодаря им всё запускается одной командой `kubectl apply -f hw2/k8s/` без падений подов.

## Как сервисы взаимодействуют

```
Браузер
  -> minikube service (туннель на 127.0.0.1)
  -> Service trade-app (NodePort)
  -> поды trade-app (2..N реплик)
  -> Service postgres
  -> под postgres-0 -> PVC

Job trade-migrate -> Service postgres
```

- Браузер открывает фронтенд и API с одного адреса, запрос через Service `trade-app` попадает в один из готовых подов приложения.
- Приложение подключается к базе по `DATABASE_URL` с хостом `postgres`, это имя резолвит DNS кластера в Service `postgres`.
- Job миграций ходит в базу через тот же Service.
- Реплики приложения между собой не общаются, всё состояние в Postgres. Поэтому приложение можно масштабировать, а одновременные покупки одного лота на разных подах разруливает база (`SELECT ... FOR UPDATE`).

Порядок запуска: база -> миграции -> приложение. Его обеспечивают initContainers: все поды создаются сразу, но Job ждёт базу, а приложение ждёт миграции.

## Масштабирование

```bash
kubectl -n trade scale deployment/trade-app --replicas=4
```

Масштабируется только приложение, Postgres остаётся в одной реплике. Проверил гонку: 20 одновременных покупок одного лота на 4 репликах дали один `200` и 19 `409`.

## Как запустить

```powershell
minikube start --driver=docker --container-runtime=docker
# сборка образов, см. выше
kubectl apply -f hw2/k8s/
kubectl -n trade get pods
minikube service trade-app -n trade
```

Удалить: `kubectl delete -f hw2/k8s/`.

## Ограничения

- Пароль от базы лежит в Secret в репозитории, для учебного проекта это нормально.
- Postgres в одном экземпляре, без репликации и бэкапов.
- Вход снаружи через NodePort и `minikube service`, без Ingress.
